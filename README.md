# Vigent

پلتفرم ایجنت هوش مصنوعی چندکاناله (وب‌سایت، واتس‌اپ، تلگرام، بله، اینستاگرام) با پایگاه دانش، اتوماسیون فروشگاهی و صورتحساب.

اتصال هوش مصنوعی با حساب مرکزی ویجنت و متغیرهای محیطی سمت سرور مدیریت می‌شود؛ کاربر هیچ کلید AI وارد نمی‌کند. اشتراک ماهانه امکانات و ظرفیت پلتفرم را پوشش می‌دهد و اعتبار پیش‌پرداخت پاسخ فقط پس از تولید موفق پاسخ کسر می‌شود (در خطا یا لغو، رزرو اعتبار آزاد می‌شود). اعتبار پاسخ یک پلن مستقل یا بستهٔ پیام ماهانه نیست.

حافظهٔ چت به جلسهٔ فعال محدود است: اولین پیام مشتری پس از حداقل ۴۸ ساعت بی‌فعالیتی، جلسهٔ جدیدی آغاز می‌کند. متن و خلاصهٔ جلسه‌های قبلی وارد پاسخ ایجنت نمی‌شوند؛ سابقه حذف نمی‌شود و مرز جلسه‌ها با توضیح روشن در داشبورد و پنل ادمین نمایش داده می‌شود. رویدادهای سیستمی این فاصله را تمدید نمی‌کنند. مالکیت اپراتور و اطلاعات پروفایل مخاطب مستقل از حافظهٔ پیام‌ها هستند.

در هر جلسه، پیام‌های کوتاه بدون خلاصه‌سازی حفظ می‌شوند. وقتی تاریخچهٔ خام از حدود ۳۰۰۰ توکن تخمینی عبور کند، پیام‌های قدیمی به خلاصه‌ای فشرده از اطلاعات مشتری، هدف، تصمیم‌ها و قدم بعدی تبدیل می‌شوند؛ حدود ۱۶۰۰ توکن از پیام‌های اخیر کامل می‌ماند. تخمین بر اساس حجم UTF-8 است و شمارش دقیق مدل نیست. سقف محافظتی ۸۰ پیام از بارگیری نامحدود جلوگیری می‌کند؛ جدیدترین پیام حتی اگر طولانی باشد کامل حفظ می‌شود. خلاصه با مدل اقتصادی ساخته و مصرف آن با نوع `SUMMARY` ثبت می‌شود. ارسال خلاصه همراه هر پاسخ نیز توکن ورودی مصرف می‌کند.

خلاصه فقط پیام‌های پردازش‌نشدهٔ همان جلسه را به‌صورت تجمعی دریافت می‌کند. در خطای سرویس یا نبود بودجه، خلاصهٔ معتبر قبلی و بخش اخیرِ محدودشده استفاده می‌شود؛ بقیه برای تلاش بعدی باقی می‌ماند. اولین خلاصه‌سازی جلسهٔ طولانی ممکن است پاسخ را کندتر کند و خلاصه تضمین حفظ تک‌تک جزئیات نیست. خلاصهٔ انتقال به اپراتور جداست و پس از شروع جلسهٔ جدید از پیام‌های همان جلسه بازسازی می‌شود.

حافظهٔ بین‌کانالی نیز فعال است: شمارهٔ نرمال‌شده معیار اصلی و قطعی یکپارچه‌سازی مخاطب است. پس از ادغام CRM، در شروع یک thread تازه یا هنگام ارجاع‌هایی مثل «کدومش؟»، «همون قبلی» و «ادامه بدیم»، حداکثر ۳۲ پیام مرتبط از سه گفتگوی دیگر همان مخاطب و همان ایجنت (فقط کانال‌های متفاوت و حداکثر ۱۸۰ روز اخیر) در یک بلوک دادهٔ محدود وارد پاسخ می‌شود. نام یا username هرگز مبنای اتصال نیست. در نوبت‌های مستقل که تاریخچهٔ محلی کافی است، سابقهٔ کانال دیگر اصلاً ارسال نمی‌شود تا هم هزینه پایین بماند و هم موضوع قدیمی کیفیت پاسخ را کم نکند. بودجهٔ recall حدود ۱۲۰۰ توکن است.

خلاصهٔ اپراتور هزینهٔ جداگانهٔ همیشگی ندارد: گفتگوهای کوتاه با استخراج deterministic و ساختار «درخواست‌ها، آخرین پاسخ، وضعیت و قدم بعدی» خلاصه می‌شوند. گفتگوهای بلند ابتدا از rolling memory موجود استفاده می‌کنند و دوباره هزینه AI نمی‌دهند. فقط handoff طولانی‌ای که rolling memory ندارد، یک‌بار با مدل اقتصادی ارتقا داده می‌شود. خلاصه در هر انتقال یا resolve مجدد تازه‌سازی می‌شود تا پیام‌های جدید پشت خلاصهٔ قدیمی پنهان نمانند.

Preview تنظیمات ایجنت و کانال‌های واقعی از یک موتور پاسخ و یک سیاست History استفاده می‌کنند. شناسهٔ Conversation در Preview داخل `sessionStorage` همان تب نگه داشته می‌شود تا refresh باعث فراموشی نشود؛ دکمهٔ «گفتگوی جدید» عمداً آن را پاک می‌کند. کانال‌های پیام‌رسان thread را با شناسهٔ پایدار خود پلتفرم بازیابی می‌کنند.

مقادیر پیش‌فرض را می‌توان هنگام استقرار با `AI_HISTORY_TOKEN_BUDGET`، `AI_HISTORY_RECENT_TOKEN_TARGET`، `AI_HISTORY_MESSAGE_LIMIT`، `AI_CONVERSATION_IDLE_HOURS`، `AI_CROSS_CHANNEL_MEMORY_DAYS`، `AI_CROSS_CHANNEL_TOKEN_BUDGET` و `AI_CROSS_CHANNEL_MESSAGE_LIMIT` تنظیم کرد. کد برای جلوگیری از هزینه یا Context نامحدود، روی هر مقدار بازهٔ امن اعمال می‌کند.

پیش از اجرای این نسخه، migration مربوط به `ConversationMemory` را با `npm run db:deploy` اعمال کنید.

## پیش‌نیازها

- Node.js 22+
- PostgreSQL 16 با extension `pgvector`
- Redis
- ذخیره‌سازی S3-سازگار (پیش‌فرض: MinIO خودمیزبان)

## راه‌اندازی توسعه (لوکال)

```bash
npm install
cp .env.example .env   # مقادیر را پر کن — جزئیات هر متغیر داخل همین فایل توضیح داده شده
npx prisma migrate dev
npm run dev             # http://localhost:3003
```

برای پردازش پس‌زمینه (ایندکس دانش، امبدینگ و…) در یک ترمینال جدا:

```bash
npm run worker
```

یا برای توسعه‌ی سریع بدون صف، در `.env` بگذار `DISABLE_QUEUE="1"` تا پردازش‌ها بدون نیاز به `worker` به‌صورت درجا انجام شوند.

## اسکریپت‌های مفید

| دستور | کاربرد |
|---|---|
| `npm run dev` | اجرای Next.js در حالت توسعه |
| `npm run build` / `npm run start` | build و اجرای production |
| `npm run worker` | پردازشگر پس‌زمینه (BullMQ) |
| `npm run db:migrate` | ساخت/اجرای migration در توسعه |
| `npm run db:deploy` | اعمال migration‌ها در production |
| `npm run db:studio` | باز کردن Prisma Studio (مرور/ویرایش دیتابیس) به‌صورت لوکال |
| `npm test` | اجرای تست‌ها (Vitest) |

## استقرار روی سرور (production)

اسکریپت‌های زیر داخل پوشه‌ی [`deploy/`](deploy/) قرار دارند:

1. **اولین بار روی سرور تازه** (Ubuntu 22.04/24.04):
   ```bash
   bash deploy/setup-server.sh
   ```
   PostgreSQL + pgvector، Redis، Node.js، PM2 و MinIO را نصب و `.env` را خودکار پر می‌کند (شامل اعتبارنامه‌ی پنل ادمین `/admin`). idempotent است — اگر سرویسی از قبل نصب باشد رد می‌شود.

2. **هر بار که کد جدید push شد**، روی سرور:
   ```bash
   bash deploy/deploy.sh
   ```
   `git pull` → نصب پکیج‌ها → `prisma migrate deploy` → `build` → ری‌استارت بدون قطعی با PM2.

3. **بک‌آپ شبانه‌ی دیتابیس** به‌صورت خودکار توسط `setup-server.sh` روی cron تنظیم می‌شود (هر شب ساعت ۳، اسکریپت [`deploy/backup.sh`](deploy/backup.sh)).

4. **Prisma Studio امن برای مالک پلتفرم** — بعد از اولین deploy، یک‌بار روی سرور اجرا کنید:
   ```bash
   bash deploy/setup-db-studio.sh
   ```
   Studio فقط روی loopback اجرا می‌شود و Nginx آن را روی `https://YOUR_DOMAIN:8443` ارائه می‌کند. دسترسی با همان session امن `/admin` کنترل می‌شود؛ رمز دوم لازم نیست. با کلیک روی «دیتابیس Prisma Studio» در پنل، Studio در تب جدید باز می‌شود. اگر گواهی TLS مسیر سفارشی دارد، متغیرهای `PRISMA_STUDIO_TLS_CERT_PATH` و `PRISMA_STUDIO_TLS_KEY_PATH` را در `.env` تنظیم کنید.

پیامک OTP از طریق پروکسی PHP روی هاست ایرانی ارسال می‌شود چون IPPanel فقط IP ایران را می‌پذیرد — جزئیات در [`deploy/ippanel-proxy/`](deploy/ippanel-proxy/) و کامنت‌های `.env.example`.
